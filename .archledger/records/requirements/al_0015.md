## Requirement

Repeated import and watch runs must not duplicate accounting rows. Each `UsageEvent`
carries a `global_dedup_key` that is unique in the SQLite database. Rows with matching
dedup keys are skipped.

## Rationale

- `toktrail watch` runs continuously; the same source events appear in every scan.
- Users may run `toktrail import` multiple times against the same source.
- Duplicate rows would inflate token counts and cost estimates.

## Source

- `toktrail/_db/core_db.py:insert_usage_events()` — dedup logic
- `toktrail/models.py:UsageEvent.global_dedup_key` — dedup key field
